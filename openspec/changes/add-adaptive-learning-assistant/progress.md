## 状态定义

- `⏳ 未开始`：尚未修改业务代码。
- `🔄 进行中`：已有实施变更，但计划步骤尚未全部完成。
- `🧪 待验证`：实现结束，正在执行测试、验收或代码审查。
- `✅ 已完成`：计划步骤全部勾选，相关测试和构建通过，完成总结已经落库。
- `⛔ 阻塞`：存在无法在当前授权或环境内解决的外部阻塞。

## 进度维护规则

1. 开始切片时，将本页及对应计划的状态改为 `🔄 进行中`。
2. 每完成一个最小任务，必须在同一轮工作中立即同步记录，不允许推迟到切片结束后补记。
3. 同步记录至少包括：勾选对应计划步骤、更新 [tasks.md](tasks.md) 中已实际完成的 OpenSpec 总任务、补充必要的验证证据，并更新本页状态。
4. 每个已完成任务必须使用独立 Git 提交固定；提交应同时包含实现、测试和对应进度文档，确保代码状态与文档状态一致。
5. 未通过验证的任务不得勾选为完成；应保持 `🔄 进行中` 或标记为 `⛔ 阻塞`，并记录原因。
6. 一个任务完成并同步提交后，才能开始下一个任务。
7. 切片实现结束后进入 `🧪 待验证`，执行完整测试、构建和代码审查。
8. 仅当切片验证通过且生成 `summaries/0x-*.md` 后，才能标记为 `✅ 已完成`。
9. Git 提交用于证明变更历史；进度页、计划复选框和完成总结用于说明当前状态。
