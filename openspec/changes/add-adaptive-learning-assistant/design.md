## Context

Super Admin 当前是 NestJS、Prisma/SQLite、BullMQ/Redis、Vue 3 和动态 ToolManifest 组成的单用户工具平台。现有知识采集模块能从 Chrome 扩展提交的页面快照中提取 Markdown，但内容没有用户所有权、版本、学习结构或掌握证据；现有 API Token 也是平台级而非用户级。

本变更同时引入多用户认证、统一学习来源、自适应教学、原子笔记和平台级后台管理，涉及前后端、数据库、异步任务、扩展授权和 AI 编排。完整产品决策和验收基线见 `../../../docs/design.md`，批准的交互原型见 `../../../docs/design-prototypes/learning-assistant-v0.html`。

## Goals / Non-Goals

**Goals:**

- 让用户从文章、EPUB 或文本 PDF 建立明确学习目标，并通过主动解释和迁移任务形成可验证理解。
- 让教学路径根据回答自适应，同时保持评价 Rubric、权限边界和结构输出稳定。
- 让学习会话在刷新、关闭页面、网络失败和服务重启后安全恢复。
- 让来源、会话、证据、画像和笔记始终归属于认证用户并相互隔离。
- 让管理员管理整个平台的用户、工具、模型、资源、任务和审计，而不介入教学或查看用户内容。
- 保留现有知识采集与 ToolManifest/BullMQ 模式，并以迁移而非旁路复制接入学习系统。

**Non-Goals:**

- 不支持扫描 PDF/OCR、视频、音频或受 DRM 保护的电子书。
- 不引入向量数据库、多 Agent 协作、知识图谱数据库或自动外部搜索。
- 不根据职业硬编码教学流程，不把阅读量或问答次数当成掌握证明。
- 不允许 Agent 未经确认保存笔记、决定学习目标或修改用户内容。
- 不提供管理员模拟登录、默认内容查看或人工修改掌握度。

## Decisions

### 1. 使用模块化单体承载领域真相

在现有 NestJS 应用中增加 `auth/users`、`learning-sources`、`adaptive-tutoring`、`learner-profile`、`atomic-notes` 和 `platform-administration` 边界。Prisma/PostgreSQL 是用户、来源、项目、会话、证据、笔记、配额和审计的唯一业务真相。

选择模块化单体是因为当前系统规模不需要分布式服务，事务、所有权和迁移在单库中更容易验证。备选微服务会提前引入跨服务一致性和部署复杂度，因此不采用。

### 2. LangGraph 只负责教学执行编排

LangGraph Graph State 只保存当前节点、当前问题、待恢复 Interrupt、临时结构输出引用和执行游标；Checkpoint 存储在 PostgreSQL。LangGraph 节点通过领域服务读取和写入业务数据，不能成为掌握度或笔记的第二套数据库。

LangChain 只用于 OpenAI-compatible 模型适配、Prompt 组合和结构化输出解析。模型调用统一经过 `ModelGateway`，记录用途、模型、Prompt 版本、Token、耗时、结构校验和后备结果。

相较纯对话或固定状态机，该边界同时提供可恢复执行与受约束的策略选择；相较多 Agent，状态归属和失败恢复更清晰。

### 3. 评价与教学动作分离

教学节点从允许动作集合中选择 `EXPLAIN`、`ASK_RECALL`、`ASK_SELF_EXPLAIN`、`ASK_TRANSFER`、`GIVE_HINT`、`GIVE_EXAMPLE`、`COMPARE`、`CHALLENGE`、`SUMMARIZE` 或 `MAKE_NOTE`。独立评价节点使用稳定 Rubric 和当前来源版本锚点评价回答。

只有结构校验通过的最终 `EvaluationResult` 才能写入理解证据并更新概念状态。迁移任务通过是产生 `TRANSFER_VALIDATED` 的唯一方式；模型自由文本、阅读进度和答题次数都不能直接提升掌握度。

### 4. 来源统一为版本化模型

网页采集、EPUB 和文本 PDF 都创建 `LearningSource`，原始文件或页面快照对应不可变 `SourceVersion`。段落和章节生成稳定来源锚点；内容地图和学习单元引用具体版本。

上传文件先校验大小、扩展名、声明 MIME 和文件签名，再写入对象存储并创建 BullMQ 解析任务。扫描 PDF 返回 `SCANNED_PDF_UNSUPPORTED`，不能继续生成空地图。网页采集继续以内联方式提取，但结果写入同一来源模型。

### 5. 用户确认学习契约和单元

开始学习前，用户确认预期能力、时间预算、已有基础以及 Agent 建议的学习单元。用户可以拆分、合并、排序或跳过单元；未确认的计划不能创建学习会话。

专注学习页面一次只呈现一个主要思考任务。内容地图、原文证据和笔记草稿使用抽屉，降低注意力竞争。

### 6. 原子笔记从用户表达派生

Agent 只能从用户回答和已确认上下文生成笔记草稿，草稿保存和最多三个链接建议都需要用户确认。每条笔记保留来源版本、来源锚点和产生它的回答引用；Markdown 导出只包含已确认笔记。

### 7. 完整认证、所有权和最小权限

Web 使用短期访问令牌和可撤销、轮换的刷新令牌；密码使用 Argon2id；邮件通过 `MailService` 抽象发送。每个领域查询必须同时包含资源 ID 和可信认证上下文中的 `userId`。

Chrome 扩展使用用户创建、仅显示一次、哈希存储且带 `capture:create` 作用域的 Token。Token 不能读取学习数据或执行管理操作。`USER` 只能访问自己的资源；`ADMIN` 获得平台管理接口，但默认仍不能读取用户正文、回答、笔记或 Graph State。

### 8. 平台后台与学习工具分离

侧边栏新增“学习助手”和仅管理员可见的“后台管理”。不存在独立“学习助手管理”；学习助手的模型、Prompt、文件限制和策略开关位于“后台管理 → 工具管理 → 学习助手”。

后台包含用户与角色、工具、模型服务、配额、跨工具任务、系统状态和审计。角色或账号状态变更、会话撤销、配额变更、模型配置发布和任务重试必须写入审计事件。系统必须保护最后一个有效管理员。

### 9. 异步任务与实时轮次分工

EPUB/PDF 解析、内容地图、大型导出和清理进入 BullMQ；实时教学轮次不进入队列，通过基于 `fetch` 的 SSE 返回节点进度和用户可见增量文本。客户端只在最终结构结果通过校验并成功写入领域数据后更新掌握状态。

提交回答和恢复 Interrupt 都要求客户端幂等键。可重试任务必须声明幂等行为；管理员不能重试非幂等或明确不可恢复的失败。

### 10. PostgreSQL 和对象存储是首版基础设施

SQLite 无法同时满足多用户生产运行、LangGraph PostgreSQL Checkpoint 和更强并发要求，因此首版迁移到 PostgreSQL。原始 EPUB/PDF 使用对象存储抽象，开发环境可使用本地兼容实现，生产环境使用 S3-compatible 服务。

## Risks / Trade-offs

- **模型评价不稳定** → 使用结构 Schema、稳定 Rubric、来源锚点、独立评价节点、后备模型和人工黄金数据集；失败时不写掌握状态。
- **Prompt Injection 通过来源内容影响工具或权限** → 来源文本始终作为不可信数据，工具、权限、Schema 和评分标准由系统层固定。
- **LangGraph Checkpoint 与领域数据不一致** → 领域写入使用幂等键和事务；Checkpoint 只保存执行游标，恢复时重新读取领域真相。
- **大型书籍解析耗时或失败** → 对象存储加 BullMQ、明确阶段状态、质量告警和可重试边界；扫描 PDF 早期拒绝。
- **多用户迁移暴露历史数据** → 历史内容迁移给初始管理员，所有新查询强制所有权条件，并增加跨用户 IDOR 测试。
- **平台管理员权限过大** → 管理 API 单独授权、内容字段不进入管理 DTO、密钥遮罩、高风险操作填写原因并审计。
- **变更范围较大** → 按基础设施、认证、来源、教学、笔记、后台和质量验证分波次交付，每个波次保持可构建和可回滚。

## Migration Plan

1. 为当前 SQLite 创建一致性备份，并在维护窗口冻结写入。
2. 部署 PostgreSQL、对象存储、SMTP 配置和新 Prisma schema，运行 Prisma Client 生成与迁移验证。
3. 创建初始管理员；将现有 `KnowledgeItem` 迁移为该管理员所有的 `LearningSource` 和首个 `SourceVersion`，保留原 ID 映射和 Job 关联。
4. 将现有平台 Token 撤销，要求用户登录后创建新的 `capture:create` Token；扩展重新授权。
5. 先启用认证和所有权读路径，再启用 EPUB/PDF 导入、教学 Graph、笔记与后台管理。
6. 对迁移数量、来源内容哈希、任务关联、跨用户隔离和 Checkpoint 恢复执行验证后开放写流量。

回滚时停止新写入，禁用学习助手 ToolManifest 和新管理路由，恢复旧应用与 SQLite 备份。迁移期间产生的新 PostgreSQL 数据不自动回写 SQLite，因此开放新写流量后回滚需要显式导出或接受恢复点之后的数据丢失。

## Open Questions

无阻塞性开放问题。模型供应商、对象存储实现和 SMTP 服务通过部署配置选择，不改变本规格中的接口与验收行为。
